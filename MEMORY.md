# Project memory

Keep this file short (about 50 lines maximum). Update it when implementation changes make a note obsolete; remove stale details instead of appending a history log. See [AGENTS.md](./AGENTS.md) for standing instructions and verification commands.

## Current state

- PSPMan aims to catalog, manage, and deploy PSP game collections across removable media. The [README](./README.md) gives the product overview.
- Game catalog CRUD is implemented across Core, SQLite, and the Desktop UI. Deployment and removable-media handling are not implemented yet.
- [PSPMan.slnx](./PSPMan.slnx) contains Core, Infraestructure, Desktop, and their xUnit test projects targeting .NET 10.
- [Core](./src/PSPMan.Core/) contains game record types, rules, and a repository contract/service with CRUD support alongside a placeholder `Class1`; [Infraestructure](./src/PSPMan.Infraestructure/) contains a SQLite CRUD repository and placeholder `Class1`; [Core.Tests](./tests/PSPMan.Core.Tests/) contains rule/service tests and an empty sample test; [Infraestructure.Tests](./tests/PSPMan.Infraestructure.Tests/) uses disposable SQLite catalogs.
- [Desktop](./src/PSPMan.Desktop/) composes a local SQLite catalog and Core service at startup. Its typed-bound window lists saved games, shows an empty state and selected-record details, and provides an editor with constrained choices, validation, add/edit actions, and inline confirmed deletion. Exact decompressed bytes and a binary-unit readable size appear in the editor and details. Catalog and operation errors appear above the content; confirmed changes remain visible after a failed refresh. [Desktop.Tests](./tests/PSPMan.Desktop.Tests/) covers composition, view models, SQLite-backed startup, and headless empty/list/create/detail, validation, duplicate create/edit, offline edit, failed save, confirmed/cancelled/failed delete, and corrupt-catalog startup flows.
- Infraestructure references Microsoft.Data.Sqlite 10.0.13 and SQLitePCLRaw.bundle_e_sqlite3 2.1.14; the explicit native-bundle version avoids a known vulnerability warning from the older transitive package. A new catalog gets a GameRecords table. Existing catalogs undergo read-only integrity, schema, and record validation before any index migration; corrupt data raise InvalidDataException without recovery or overwrite. Runtime reads also validate saved fields; SQLite corruption and malformed records raise InvalidDataException, while ordinary storage failures remain distinct. Two case-sensitive partial unique indexes cover DVD (Medium, DvdNumber, Location) and non-DVD (Medium, Location); their creation is transactional so a duplicate legacy catalog retains its rows and old schema. CRUD statements are parameterized and missing IDs raise errors; subsequent connections use ReadWrite to avoid recreating a lost catalog.

- For game-record validation, DVD number zero normalizes to null; Notes are limited to 2,500 UTF-16 code units (`string.Length`), as approved for T03.
- Location validation uses medium-rooted `/` paths and no filesystem access; names such as `/mnt/usb/game.rar` are accepted by syntax without guessing a host mount point.
- Duplicate identity compares Medium and Location ordinally, plus normalized DVD Number only for DVD; the service must exclude the record being edited when checking others.
- The Core catalog contract uses synchronous operations; service results distinguish an absent record, field validation errors, ordinary storage failures, and corruption. Create returns the saved record; Edit validates before repository access, preserves the record ID, and excludes that ID from duplicate checks. Delete checks for the record and returns success only after repository deletion. Desktop reloads the list after successful mutations; corruption detected at startup or during a session disables further catalog writes without repair.
- Desktop [CatalogStartup](./src/PSPMan.Desktop/CatalogStartup.cs) uses the OS local application-data directory under `PSPMan/catalog.db`; startup failure leaves the service unavailable and exposes a visible English error. The main view model lists records on construction; list failures show an error, not an empty state. Tests pass a temporary root, leaving the user's catalog untouched.
- Desktop [GameEditorViewModel](./src/PSPMan.Desktop/ViewModels/GameEditorViewModel.cs) keeps numeric input as text to report parse errors, runs Core validation through Check fields, revalidates after subsequent edits, and clears a hidden DVD number when the medium changes. - Core [GameCatalogImportRules](./src/PSPMan.Core/Games/GameCatalogImportRules.cs) maps required schema headings with ordinal case-insensitive comparison and the last duplicate column. Its read-only map retains total header width, including ignored extra columns. Any char.IsWhiteSpace character in any heading rejects the header; missing headings return a deterministic error and no partial map. Unknown headings without whitespace are ignored.
- Import typed-value helpers match only canonical schema labels with ordinal case-insensitive comparison, rejecting numeric enum values and whitespace. DvdNumber accepts empty or unsigned Int32 digits, normalizing zero to null; SizeBytes requires positive Int64 digits. NumberStyles.None and InvariantCulture reject signs, whitespace, grouping, decimals, exponents, and overflow. Failures return GameRecordValidationError for the affected field.
- TryMapGameRow maps complete rows through heading indices, aggregates typed conversion failures, then reuses GameRecordRules (including DVD-only numbering and the 2,500 UTF-16-unit Notes limit). It returns no record on error and never mutates cells. UndoFormulaProtection removes one initial tab only when the following first non-whitespace character is =, +, -, or @; all other text is preserved. TryMapSourceRow checks total header width (including extra/repeated headings), ignores surplus cells, and returns one GameCatalogImportRowError per rejected row with its physical start line, message, and field errors. Invalid rows do not prevent mapping later records.
- Core [GameCatalogCsvTokenizer](./src/PSPMan.Core/Games/GameCatalogCsvTokenizer.cs) accepts character chunks through Push and emits completed semicolon-separated records through a callback with 1-based source lines and read-only cells. It decodes quoted semicolons/doubled quotes and preserves Unicode and exact CRLF/LF within multiline fields across chunk boundaries. Complete emits a final row without a trailing newline once. CRLF counts as one physical line break; only current-record buffers are retained. Empty or spaces/tabs-only lines outside quotes are ignored; quoted empty/whitespace cells and separator-bearing rows are retained. Unexpected quotes, characters after closing quotes, and EOF inside quotes raise FormatException with the record start line and reason; a failed tokenizer cannot resume. The future preview service must discard all proposed changes after such a fatal error.
- ClassifyCandidates indexes a supplied catalog snapshot once by import identity and compares final candidates without repository access or mutation. Its read-only new/modified proposal lists retain source lines and follow source-line order; modifications retain the existing ID, while new IDs are deferred until saving. Identical matches are omitted entirely; null/empty Notes compare equally, but other text differences remain significant. Row errors stay separate from classification counts.
- Import Identity keys use Medium, ordinal case-sensitive Location, and normalized DvdNumber only for DVD, matching GameRecordRules. SelectLastValid validates each source row before updating the supplied candidate dictionary; invalid rows return a separate row error without changing it. Each identity retains only the last accepted row's immutable input and physical start line; selection order follows input processing order, not dictionary enumeration order.
- Core [IGameCatalogImportSource](./src/PSPMan.Core/Games/IGameCatalogImportSource.cs) opens a caller-owned disposable reader with Read(Span<char>). Infraestructure [FileGameCatalogImportSource](./src/PSPMan.Infraestructure/Games/FileGameCatalogImportSource.cs) reads sequentially with bounded buffers, strict UTF-8, an optional initial UTF-8 BOM, and no UTF-16/32 autodetection. Read-only handles use FileShare.Read. GameCatalogImportReadException distinguishes source open/read/encoding failures from catalog corruption and preserves the inner exception. Dispose releases the handle; no catalog or source writes occur.
- Import readers CaptureFingerprint hashes all raw bytes with SHA-256 (including BOM), restoring the underlying stream position without discarding decoded buffers. VerifyUnchanged checks both the held handle and a fresh open of the resolved source path against the expected hash; mismatches raise GameCatalogImportSourceChangedException, while inaccessible/unverifiable content raises GameCatalogImportReadException. An internal seekable-stream factory supports deterministic read/change failures in tests. Preview/apply must coordinate these checks; file-sharing rules do not guarantee an absolute lock against external writers.
- Core [GameCatalogImportService](./src/PSPMan.Core/Games/GameCatalogImportService.cs) Preview reads one repository snapshot, captures the source fingerprint before decoding, streams through the tokenizer/rules, and verifies unchanged content after EOF. Its immutable result contains source/fingerprint, new/modified proposals, and one error per invalid row; no-ops and superseded valid rows do not affect counts. Header-only input succeeds with zero counts; missing/invalid headers and fatal parse/read/verification errors return no preview, even after valid rows. CancellationToken is checked between synchronous operations, blocks, and records; cancellation returns a failure message and no proposals. Opened readers are disposed on all exits. Only InvalidDataException from repository snapshot access sets IsCorrupt; CSV/source failures do not. Preview never calls repository writes.
- PrepareConfirmedImport reopens the preview source and calls VerifyUnchanged with its original fingerprint before transferring ownership to GameCatalogVerifiedImportSession. Successful sessions retain the preview and an unread open reader; callers must dispose them unless consumed by Apply, and disposal is idempotent. Changed/missing/unreadable/unverifiable sources or cooperative cancellation return no session and close any opened reader. Preparation neither rereads the repository nor writes records.
- Apply consumes a verified session once, verifies its source again before writes, and saves only the preview's new/modified proposals in source-line order through the repository. Creates receive new GUIDs; edits preserve IDs and can clear Notes. No-op records are never written. The result counts only completed writes and retains their saved records; session disposal follows success, error, or cancellation. Ordinary repository errors add a source-line SaveErrors entry and continue; InvalidDataException from a repository write adds one failure, sets IsCorrupt, and stops later writes. FailedCount excludes unattempted proposals, source-check failures, and cooperative cancellation. Any error prevents IsSuccess; prior saved records and failures remain available. Apply rereads the complete CSV with the existing tokenizer, maps selected proposals by their physical starting line, and validates/compares their inputs before each write. Missing or mismatched selected rows and fatal parse/read errors stop further writes with partial results. Full source fingerprints are checked before each selected write (including buffered rows) and after EOF; this favors change detection at the cost of repeated whole-file hashing for large imports. Final verification failure prevents success even when all proposed writes completed. Source errors do not count as failed writes or catalog corruption. Game files are never accessed.
