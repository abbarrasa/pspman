# Project memory

Keep this file short (about 50 lines maximum). Update it when implementation changes make a note obsolete; remove stale details instead of appending a history log. See [AGENTS.md](./AGENTS.md) for standing instructions and verification commands.

## Current state

- PSPMan aims to catalog, manage, and deploy PSP game collections across removable media. The [README](./README.md) gives the product overview.
- Game catalog CRUD is implemented across Core, SQLite, and the Desktop UI. Deployment and removable-media handling are not implemented yet.
- [PSPMan.slnx](./PSPMan.slnx) contains Core, Infraestructure, Desktop, and their xUnit test projects targeting .NET 10.
- [Core](./src/PSPMan.Core/) contains game record types, rules, and a repository contract/service with CRUD support alongside a placeholder `Class1`; [Infraestructure](./src/PSPMan.Infraestructure/) contains a SQLite CRUD repository and placeholder `Class1`; [Core.Tests](./tests/PSPMan.Core.Tests/) contains rule/service tests and an empty sample test; [Infraestructure.Tests](./tests/PSPMan.Infraestructure.Tests/) uses disposable SQLite catalogs.
- [Desktop](./src/PSPMan.Desktop/) composes a local SQLite catalog and Core service at startup. Its typed-bound window lists saved games, shows an empty state and selected-record details, and provides an editor with constrained choices, validation, add/edit actions, and inline confirmed deletion. Exact decompressed bytes and a binary-unit readable size appear in the editor and details. Catalog and operation errors appear above the content; confirmed changes remain visible after a failed refresh. [Desktop.Tests](./tests/PSPMan.Desktop.Tests/) covers composition, view models, SQLite-backed startup, and headless empty/list/create/detail, validation, duplicate create/edit, offline edit, failed save, confirmed/cancelled/failed delete, and corrupt-catalog startup flows.
- Infraestructure references Microsoft.Data.Sqlite 10.0.13 and SQLitePCLRaw.bundle_e_sqlite3 2.1.14; the explicit native-bundle version avoids a known vulnerability warning from the older transitive package. A new catalog gets a GameRecords table. Existing catalogs undergo read-only integrity, schema, and record validation before any index migration; corrupt data raise InvalidDataException without recovery or overwrite. Runtime reads also validate saved fields; SQLite corruption and malformed records raise InvalidDataException, while ordinary storage failures remain distinct. Two case-sensitive partial unique indexes cover DVD (Medium, DvdNumber, Location) and non-DVD (Medium, Location); their creation is transactional so a duplicate legacy catalog retains its rows and old schema. CRUD statements are parameterized and missing IDs raise errors; subsequent connections use ReadWrite to avoid recreating a lost catalog.

## Details to remember

- `Infraestructure` is the existing project and directory spelling; keep it in paths and namespaces unless a rename is explicitly requested.
- [ViewLocator.cs](./src/PSPMan.Desktop/ViewLocator.cs) replaces `ViewModel` with `View` in the type's full name without changing the `ViewModels` namespace to `Views`. Check this mapping before relying on it for navigation.
- The repository-local [feature skill](./.agents/skills/feature/SKILL.md) requires a reviewable plan and user approval before changing files for a new feature.
- The skill-creator validator requires PyYAML; validate skills in an isolated Python environment when the system interpreter lacks it.
- The approved [constitution](./docs/constitution.md) sets six project principles for stack, specs, boundaries, tests, and English artifacts; apply it to future feature work.
- [Auto PR workflow](./.github/workflows/create-pr.yml) targets `dev` on branch pushes, assigns the triggering user, ensures the `review-pending` label exists, and skips branches with an existing PR. GitHub's repository setting must allow Actions to create pull requests.
- For game-record validation, DVD number zero normalizes to null; Notes are limited to 2,500 UTF-16 code units (`string.Length`), as approved for T03.
- Location validation uses medium-rooted `/` paths and no filesystem access; names such as `/mnt/usb/game.rar` are accepted by syntax without guessing a host mount point.
- Duplicate identity compares Medium and Location ordinally, plus normalized DVD Number only for DVD; the service must exclude the record being edited when checking others.
- The Core catalog contract uses synchronous operations; service results distinguish an absent record, field validation errors, ordinary storage failures, and corruption. Create returns the saved record; Edit validates before repository access, preserves the record ID, and excludes that ID from duplicate checks. Delete checks for the record and returns success only after repository deletion. Desktop reloads the list after successful mutations; corruption detected at startup or during a session disables further catalog writes without repair.
- Desktop [CatalogStartup](./src/PSPMan.Desktop/CatalogStartup.cs) uses the OS local application-data directory under `PSPMan/catalog.db`; startup failure leaves the service unavailable and exposes a visible English error. The main view model lists records on construction; list failures show an error, not an empty state. Tests pass a temporary root, leaving the user's catalog untouched.
- Desktop [GameEditorViewModel](./src/PSPMan.Desktop/ViewModels/GameEditorViewModel.cs) keeps numeric input as text to report parse errors, runs Core validation through Check fields, revalidates after subsequent edits, and clears a hidden DVD number when the medium changes. Add and Edit use Core service results; only confirmed writes update the list/details. Failed writes keep the draft and saved view unchanged; a failed post-save refresh keeps the confirmed change visible with an error. Edit mode fixes the target ID when opened, even if the list selection changes; Cancel edit discards the draft. Delete confirmation also fixes its target ID; Cancel leaves the catalog unchanged, failure leaves the record visible, and successful deletion removes only the catalog row even if refresh fails.
- Headless functional tests use Avalonia.Headless 12.1.4 with manual sessions and the existing xUnit 2 project. A test-only application supplies FluentTheme; UI tests run in a nonparallel collection, create disposable SQLite catalogs, and pass without DISPLAY or WAYLAND_DISPLAY. Named controls in the real window allow binding and keyboard-action checks; flush dispatcher jobs after list selection before focusing an edit button. A moved disposable catalog simulates failed saves/deletes without touching user data; a byte-corrupt disposable catalog tests startup error handling without repair.
- The [game record CRUD specification](./specs/001-crud-game/spec.md) defines required fields, DVD-only numbering, manually entered decompressed size, case-sensitive location/medium/DVD duplicate identity, confirmed record-only deletion, and offline editing. Its [implementation plan](./specs/001-crud-game/plan.md) and [tasks](./specs/001-crud-game/tasks.md) are complete (T01–T25). The [coverage report](./specs/001-crud-game/coverage.md) maps every FR to passing tests: 178 tests pass; Core 100% line/branch, Infraestructure 98.02%/92.85%, Desktop 91.04%/86.61% in their owning test suites. The [graphical validation](./specs/001-crud-game/manual-validation.md) passed on Linux/X11 with an isolated catalog and no product deviations; it covered create, list/details, duplicate rejection, offline edit, and cancel/confirm deletion.
- CSV export is implemented across Core, Infraestructure, and Desktop with UTF-8 BOM, semicolon delimiters, quoted text, an export-only tab prefix for formula-like text, destination choice, replacement consent, and staged writes that preserve existing files on failure. The [export plan](./specs/002-export-games/plan.md) and [tasks](./specs/002-export-games/tasks.md) document the completed T01–T23 implementation. The [coverage report](./specs/002-export-games/coverage.md) records 278 passing tests and owning-suite line/branch rates: Core 98.53%/96.36%, Infraestructure 98.49%/88.63%, Desktop 90.00%/86.44%. Linux/X11 validation passed; Excel-specific display and formula nonexecution remain unverified because Excel is unavailable.
- The [export specification](./specs/002-export-games/spec.md) and serializer agree on seven headings in order: Title, Medium, DvdNumber, Location, Format, SizeBytes, Notes, with Medium values Dvd/Usb/MemoryCard and Format values ISO/CHD. The shared Core schema defines heading order; export omits approximate size while Desktop retains readable sizes. Exact-output and SQLite-backed functional tests verify canonical labels, quoting, and formula protection; the export plan/task acceptance text reflects this revised contract.
- The [CSV import specification](./specs/003-import-games/spec.md) requires the same seven headings in any order, case-insensitive matching, last repeated column, extra-cell tolerance, and rejection of short rows. Any whitespace in a heading fails the preview; whitespace in Medium/Format values rejects that row. Blank lines or lines containing only spaces/tabs outside quotes are ignored; no fixed CSV size limit applies. Preview precedes confirmation; a read error before preview cancels it, while a post-preview read error stops import and retains saved games. Only unchanged previewed CSV may be used; a change before saving aborts, and one after saving starts stops further writes. Matching records are fully replaced by Medium/ordinal Location/DVD identity; last valid duplicate wins. Formula-like text loses one protective tab. The app must provide a CSV template showing all allowed Medium and Format values with other required fields blank, so importing it unchanged creates no games; no open questions remain.
- The [import implementation plan](./specs/003-import-games/plan.md) and [dependency-ordered tasks](./specs/003-import-games/tasks.md) guide one approved task at a time. T01–T06 are complete. Core [GameCatalogCsvTemplate](./src/PSPMan.Core/Games/GameCatalogCsvTemplate.cs) generates UTF-8 BOM/CRLF examples for Dvd/ISO, Usb/CHD, and MemoryCard/ISO with other fields empty; required-field validation rejects each example. Template and export share schema labels and CSV encoding. Template saving/UI, heading/row interpretation, preview/confirmation, source checks, and import writes remain unimplemented.
- Core [GameCatalogCsvTokenizer](./src/PSPMan.Core/Games/GameCatalogCsvTokenizer.cs) accepts character chunks through Push and emits completed semicolon-separated records through a callback with 1-based source lines and read-only cells. It decodes quoted semicolons/doubled quotes and preserves Unicode and exact CRLF/LF within multiline fields across chunk boundaries. Complete emits a final row without a trailing newline once. CRLF counts as one physical line break; only current-record buffers are retained. Empty or spaces/tabs-only lines outside quotes are ignored; quoted empty/whitespace cells and separator-bearing rows are retained. Unexpected quotes, characters after closing quotes, and EOF inside quotes raise FormatException with the record start line and reason; a failed tokenizer cannot resume. The future preview service must discard all proposed changes after such a fatal error.
- An imported row identical to its matching catalog record is a no-op and is omitted from preview counts; absent and empty Notes compare as equivalent so an export/import round trip does not rewrite empty Notes.
