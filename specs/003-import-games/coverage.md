## Observed gaps and limits

- **Core: 17 lines and 12 branches uncovered in its owning suite.** Gaps include invalid schema-label fallbacks, the direct short-row mapping precondition, tokenizer defensive/terminal paths, reusing an already consumed session before disposal, a reread with no header, and unexpected confirmation exceptions. `ExportDestinationSnapshot` is exercised by storage tests instead. Normal row-width validation, malformed CSV, cancellation, source changes and corruption have passing evidence; these gaps are defensive paths rather than additional supported CSV behavior.
- **Infraestructure: 10 lines and 8 branches uncovered.** Six lines concern rejecting a source stream that cannot read/seek and disposing after reader-construction failure. Four concern unusual SQLite integrity/conversion exceptions. Remaining branches include constructor guards and defensive atomic-writer checks. Real-file UTF-8, full hashes, same-size/timestamp changes, path replacement/disappearance, injected I/O errors, SQLite persistence and protected publication are covered. Further exceptional-path coverage would require more adapter fault injection.
- **Desktop: 128 lines and 65 branches uncovered.** Major gaps are real graphical App/Program startup, ViewLocator, native Avalonia file/folder pickers, and platform path fallbacks. Headless tests use a test application and injected pickers. Import-specific gaps include unexpected-exception catch blocks, nullable result fallbacks and defensive conditions; the Core service normally returns typed failures instead of throwing. Four XAML lines for displaying per-record save-error item content are not executed by the headless suite, although view-model tests verify the save-error data and other headless tests verify summary/source-error feedback. Existing CRUD/export guards and rare destination failures contribute to the whole-project figures.
- Coverage demonstrates execution, not exhaustive correctness or native-dialog behavior. This run is on Linux and does not certify other operating systems, Excel rendering, or Excel formula nonexecution. No throughput benchmark or machine-independent capacity guarantee is implied. Source sharing/fingerprints detect observed changes but do not provide an absolute cross-platform lock against external writers.
- All thirteen FRs have automated evidence above. The [graphical walkthrough](./manual-validation.md) records the subsequent T34 observations and distinguishes automated-only read-failure evidence; Excel-specific acceptance remains pending because Excel was unavailable.
